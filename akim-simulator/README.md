# Аким на 5 часов

Симулятор Astana Innovations: бюджет 100, ровно 5 решений, 5 синтетических районов и 14 мероприятий. Сервер проверяет правила, считает Score, предлагает допустимые улучшения. LLM выбирает существенные аргументы из проверенных фактов.

## Сначала откройте интерфейс

**`dist/akim-standalone.html` — готовая демонстрация одним файлом.** Скачайте его отдельно или распакуйте архив и откройте двойным щелчком в браузере. Устанавливать Node.js и искать соседние `.js`/`.css` для этого варианта не требуется. Нажмите «Пример задания»: появится Score 56,54. Выбор, рекомендации, сравнение, локальное объяснение и вопросы работают без сети.

Этот файл не содержит API-ключей и использует только локальное объяснение. Для живого AI через OpenAI или NVIDIA запустите полный проект, как описано ниже. После изменения кода разработчик может обновить одиночный файл командой `python3 scripts/build-standalone.py`.

## Запуск

Установите Node.js 22 или новее с https://nodejs.org/en/download (проверено на 24). Распакуйте проект, откройте терминал в папке с `package.json`:

```sh
npm start
```

Откройте **http://localhost:3000**. Ctrl+C останавливает сервер. Внешних npm-зависимостей нет, `npm install` не требуется. Открывать HTML двойным щелчком больше не нужно: страница обращается к серверу.

```sh
npm test
```

Тесты не требуют ключей и не вызывают платные сервисы.

## Реализовано

- Все ограничения задания, лаги, три синергии, clip, критические значения и Score на сервере.
- Каталог с фильтрами, адаптивный интерфейс, графики районов, показатели и раскрытая формула.
- Сохранение до 12 сценариев в браузере, серверный пересчёт при загрузке, сравнение и экспорт JSON.
- Перебор всех допустимых замен одной меры или её района; три лучших найденных улучшения. **Глобальный оптимум не заявляется.**
- Точное распределение прироста методом Шепли для пяти мер: 32 поднабора. Вклады суммируются в общий прирост. Поднаборы — внутренние математические контрфакты, не игровые сценарии.
- Готовые HTTP-адаптеры OpenAI Responses и NVIDIA API Catalog Chat Completions. По умолчанию — явно обозначенный локальный режим. Можно задать вопрос о конкретном районе, мере или формуле.
- Проверка ответа модели, таймаут, fallback, кэш до 50 успешных разборов до перезапуска сервера.

## Подключение ИИ

Скопируйте `.env.example` в `.env`. В PowerShell:

```powershell
Copy-Item .env.example .env
```

Для OpenAI заполните:

```dotenv
AI_PROVIDER=openai
OPENAI_API_KEY=ваш_секретный_API_ключ
OPENAI_MODEL=точный_id_доступной_вам_модели
```

Для размещённой у NVIDIA модели:

```dotenv
AI_PROVIDER=nvidia
NVIDIA_API_KEY=ваш_секретный_API_ключ
NVIDIA_MODEL=точный_id_из_примера_API_модели
```

Значения справа здесь — пояснения. Реальные реквизиты указываются только в локальном `.env`. Затем перезапустите сервер. Выбирается один поставщик, оба автоматически не вызываются.

Ключ OpenAI: https://platform.openai.com/api-keys. NVIDIA: https://build.nvidia.com/settings/api-keys. Модели NVIDIA: https://build.nvidia.com. Нужна текстовая chat/instruct-модель. Model ID копируется из примера API выбранной модели, доступ и квота зависят от аккаунта. GPU-часы или учебный ваучер могут не предоставлять доступ к hosted API.

Нажмите «Пример задания», затем «Разобрать сценарий». Только метка `ИИ: openai` или `ИИ: nvidia` у успешного ответа подтверждает реальное обращение. «Настроен, не проверен» в шапке означает лишь наличие настроек. Ошибки ключа, квоты, сети или формата ответа возвращают локальный разбор с объяснением причины.

Codex/ChatGPT-кредиты и API-кредиты имеют разное назначение. Документ организаторов «OpenAI и NVIDIA» по ссылке прочитать не удалось, точный вид ваших кредитов неизвестен.

## Архитектура

| Файл | Ответственность |
|---|---|
| `public/index.html`, `public/styles.css` | Структура и дизайн |
| `public/app.js` | Кнопки, запросы, графики, сохранение |
| `server.js` | HTTP-сервер и API приложения |
| `src/engine.js` | Данные, валидатор и официальная формула |
| `src/analysis.js` | Альтернативы, Шепли, проверенные факты |
| `src/ai.js` | Запросы провайдеру, проверка ответа, fallback |
| `src/presets.js` | Два готовых сценария для демо |
| `dist/akim-standalone.html` | Одна страница для открытия без установки |
| `scripts/build-standalone.py` | Сборка одиночной страницы из тех же исходников |
| `.env.example` | Образец настроек без секретов |
| `tests/` | Расчётные, серверные тесты, имитация AI-ответов |
| `.github/workflows/tests.yml` | Автоматический запуск тестов на GitHub |

`GET /api/config` возвращает данные и статус. `POST /api/validate` проверяет промежуточный выбор. `POST /api/analyze` считает полный результат. `POST /api/explain` возвращает разбор; `POST /api/ask` принимает тот же список и строку `question`. Тело POST: `{ "choices": [{ "id": "M7", "district": "Нура" }, ...] }`. Клиентские Score, стоимость и эффекты игнорируются. Для городской меры district = null или поле отсутствует.

## Роль LLM

Сервер создаёт каталог проверенных фактов и альтернатив. Модель изучает результат и выбирает идентификаторы сильных сторон, рисков и одной рекомендации. Сервер проверяет ID и обязательное упоминание критических значений/отрицательного эффекта M11. На экран выводится текст выбранных фактов из сервера.

Это ограниченный структурированный AI-анализ: модель выбирает аргументы и приоритеты. Свободный диалог не реализован. Такая схема исключает подмену рассчитанных чисел текстом модели, но качество выбора аргументов надо оценить на живой модели перед защитой. Некорректный ответ заменяется явно обозначенным локальным разбором.

## Проверки и ограничения

24 автоматических теста: эталон, все 120 порядков пяти решений, строгий порог 40, лаги, синергии, несовместимости, бюджет, Шепли, рекомендации, серверный пересчёт, вопросы, закрытые файлы, проверка AI-ответов и кэш. Фактические проверки описаны в `docs/VERIFICATION.md`.

Ключей пользователя нет; платные запросы не выполнялись. Тестовые ответы проверяют код адаптеров, а не доступ к вашему аккаунту. Репозиторий GitHub не создан, аккаунты не подключены, публичный сайт не развёрнут.

Сервер слушает только 127.0.0.1 для локальной демонстрации. Для публичного доступа нужны авторизация, лимиты AI-расхода на пользователя, HTTPS и общий сервер/БД. Сценарии текущей версии хранятся только в браузере. Все данные синтетические, результаты не являются прогнозом для реальной Астаны.
